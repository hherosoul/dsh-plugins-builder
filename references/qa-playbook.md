# Phase 4 质检手册（运行时矩阵 + 9 维度 + 证据链）

## 运行时验证矩阵（verify_plugin.js，M2）

> 静态校验只能证明「写得像」，运行时验证才证明「跑起来是」。分层递进，每层产出结构化证据。

| 层 | 验证内容 | 手段 | 环境要求 |
|---|---|---|---|
| L1 静态 | 规则 ID 全量 | `validate_plugin.js`（M1 可用） | 无 |
| L2 构建 | TS 编译 / 打包产物生成 | `tsc` / `tsdown` / `pnpm build` | node + pnpm |
| L3 加载 | 覆盖层加载成功；`--dump-config` 出现目标层；无 FAILED fiber | `dsh ... --patch` + `--dump-config`，捕获启动日志 | dsh CLI |
| L4 行为 | 工具可被调用且返回规范值；非法配置加载失败且报错响亮；HMR 重载无残留注册；取消（signal）生效 | headless 运行 / Web UI 实测；构造边界输入 | dsh CLI（调用类用例需模型密钥） |
| L5 安装式 | 净 profile `dsh plugin add` → dump-config → 启动冒烟 | 临时 profile（`__verify_<name>` 命名），验证后强制清理 | dsh CLI |

## 证据格式（每层一份，随轮次存档）

```json
{
  "plugin": "dsh-example", "round": 1, "layer": "L3",
  "command": "dsh --profile dev --patch ./dev/cordis.yml --dump-config",
  "exit_code": 0,
  "expectation": "dump-config 出现 id=example 的层",
  "verdict": "pass",
  "evidence": "# == dsh-example ...（输出摘录）"
}
```

**判定归属**：命令执行、输出比对、退出码解析 = 脚本（计算 / 变换）；「输出是否符合预期语义」= LLM 判定，脚本只聚合。

## 诚实降级（环境三档盘点）

| 环境 | 处理 |
|---|---|
| 有 dsh CLI + 模型密钥 | L1–L5 全跑 |
| 有 dsh CLI 无密钥 | L1–L3 + L5 必跑；L4 只跑无需密钥项（配置校验失败、HMR、取消）；**未跑项显式列入「未覆盖项」** |
| 无 dsh CLI | 仅 L1–L2；报告显著标注「运行时验证未执行，交付未达可发布标准」，**禁止宣称交付完成** |

## 9 维度场景质检（代码交付版）

| # | 维度 | 定义 | 判定方式 |
|---|---|---|---|
| 1 | 调用准确性 | 工具 `description` 让模型在正确时机调用、不在错误时机调用 | **混淆矩阵**：应调用问法 ×N + 不应调用问法 ×M，算误触发 / 漏触发率（无密钥环境降级为 description 语义评审，标注未覆盖） |
| 2 | 开箱首轮 | 干净环境按 README Quickstart 一次走通（安装 → 启动 → 验证） | 逐条复制 README 命令实测，记录输出 |
| 3 | 能力边界 | 工具行为与 description 一致、不越界承诺；失败诚实（isError / 降级警示） | 边界输入实测：畸形参数 / 缺依赖 / 超时取消，看是否谎报成功 |
| 4 | 平台铁律自检 | dsh-spec.md 平台铁律逐条对照，每条可追到具体代码行 | 「宣称 → 代码」追踪：文档每条「保证 X」必须落到行 |
| 5 | 可运行性 | 干净 profile 实测可用；外部依赖三档盘点；最小真实样例 | L5 安装式验证 + 依赖矩阵（本机 node/pnpm 版本 vs 要求） |
| 6 | 正确性 / 一致性 | dispose / HMR 无残留；并发与取消正确；配置非法加载失败响亮 | HMR 重载 diff 注册表；取消用例；非法配置用例 |
| 7 | 边界正确性 | 脚本化边界（计算 / 变换 vs 识别 / 匹配）；seam 拆分有理由（无预防性拆分） | 逐脚本判定归属；拆分理由质询（出现「以后可能」→ 判失败） |
| 8 | 文档 SSOT | 规范只定义一次；README 与实际行为一致 | 验收问句（同一规范出现几处？改一处阈值要改几个文件？）+ README 命令回放 |
| 9 | 隐私 / 泄漏 | 无硬编码密钥、无个人绝对路径、示例全占位符 | 模式扫描（SEC-*）+ 语义级审计 |

**补充三件事**（happy path 测不出，命中任一判不合格）：
1. **降级路径是否诚实**——判定必须结构化传递（返回值 / 哨兵 / exit code），禁止靠在输出文本里搜关键字；
2. **依赖矩阵**——本机装齐 ≠ 用户机装齐（node / pnpm / dsh CLI 版本下限写进 README）；
3. **「宣称 → 代码」追踪**——追不到就是卖点与实现的断层。

## 迭代纪律

- 失败 → 定位「代码问题 / 配置问题 / 文档问题」→ **最小改动** → 复测。
- **任何改动后重放全量用例并 diff 上一轮**（防回归）。
- 迭代上限 3 轮；3 轮后仍有关键问题，如实告知用户并让其决策。

## 已知盲区（每份 QA-REPORT 必写进「未覆盖项」）

- 标准库校验器无完整 TS AST：启发式规则（TS-003 / TOOL-004 / TOOL-005 / CFG-002）一律 `[W]` + 语义复核归本阶段，不冒充确定性。
- 无密钥环境的调用准确性只能做 description 语义评审，混淆矩阵未执行。
- 安装式验收的临时环境污染风险：`__verify_<name>` 命名 + 验证后强制清理（清理失败 = 报错留痕）。
