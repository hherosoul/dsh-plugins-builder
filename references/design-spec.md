# Phase 2 设计判定表

## 新行为归属表（先定归属，再定形态）

| 要做什么 | 归属 | 形态提示 |
|---|---|---|
| 注册一个模型可调用的能力 | `ctx.tools.register(defineTool(...))` | 工具插件 |
| 拦截 / 观测轮次流程 | `agent/*` 事件（bail / serial / waterfall） | 事件钩子 |
| 观测工具调用结果 | `tools/result`、`session/event`（按 `event.type` 分流 `turn/*`、`tool/call`、`tool/result`） | 事件钩子 |
| 替换 / 新增执行后端 | 能力 seam（Definition / Provider / Consumer） | seam 三件套 |
| 新增模型适配器 | `ctx.llm.registerAdapter` | LLM 适配器 |
| 给其他插件提供服务 | 类形式 `extends Service` + `super(ctx, '<svc>')` | 服务插件 |
| 新增命令行 / 设置卡片 | 表层组合包 + `cmdlineArgs` / 卡片插件 | 命令或设置卡片 |
| 持久会话事实 | 会话事件（模型可见即已记录） | 事件钩子 |
| 部署策略（审批 / 限额等） | `tools/pre-execute` 等钩子，**不内建进工具** | 事件钩子 |

## 能力类型 → 模板映射

| 能力类型 | init `--kind` | 关键契约 |
|---|---|---|
| 最小验证 / 第一个插件 | `minimal` | 函数形式 + 加载日志 |
| 面向模型的工具 | `tool` | defineTool 五要素 + `inject: ['tools']` |
| 可配置插件 | `config` | Config 接口 + Schema 成对；默认值写 schema |
| 对外提供服务 | `service` | 类形式；服务名经 `super(ctx, ...)` |
| 拦截 / 观测 | `event-hook` | 四种事件模式；waterfall 必须 `next()` |
| 确需独立演进的能力 | `seam-trio` | 三包骨架；拆分必须给独立演进理由 |

## 架构决策（单包 vs 拆分）

- **默认单包**。拆 Definition / Provider / Consumer 三包必须回答：哪个角色与谁独立演进？发布节奏 / 复用面差异是什么？
- 回答含「以后可能……」→ 判预防性拆分，拒绝。
- Definition 拥有服务名与 Request/Result 类型（契约 SSOT）。

## Config 设计清单

1. 列出全部可调参数（端点 / 超时 / 阈值 / 开关 / 文案……）——**凡部署间可能不同的一律配置化**。
2. 每个参数定：类型、默认值（从宽）、约束（交 schema：`.required()` / `.union([...])`）。
3. 检验问句：**能否只在 `cordis.patch.yml` 改值而不改代码？** 不能 = 设计未完成。
4. 必填且无默认值的参数 → README 必须写明用户如何提供（配置错误要响亮，但文档要先说清）。
5. 禁止导出普通对象作 Config；禁止源码内硬编码可调参数（含 URL / 端口 / 超时字面量）。

## 事件域选择

| 场景 | 选择 |
|---|---|
| 模型可见的持久事实（轮次 / 工具记录） | 会话事件（新增模型可见输入必须新增会话事件） |
| 实时扩展 / 拦截 | Cordis 事件（`namespace/action`） |
| 需要修改流经数据 | waterfall（监听器必须 `await next()` 并返回） |
| 需要一票否决 | bail |

## 工具 DSL 五要素清单

1. `name`：kebab/snake 一致、语义化、全注册表唯一。
2. `description`：写清「何时该调用 / 何时不该 / 边界与失败语义」（模型调用准确性的唯一依据；≥20 字，禁止夸大承诺）。
3. `parameters`：每个参数 `{ type, required, description }`；显式对象节点声明 `additionalProperties`。
4. `output.schema` + `output.render`：规范值形状 + 纯函数渲染（两者成对）。
5. `execute`：只返回规范值；遵守 `exec.signal`；长任务 → `ctx.jobs.start`；失败诚实（抛异常 = isError，禁止谎报成功）。

决策问句：需要 UI 卡片？→ presenters（card 标签渲染意图：generic / terminal / diff；纯函数；结果期卡片事实经 `presentationMeta` 持久化）。需要后台长跑？→ `ctx.jobs.start`（producer 配置控制 `run_in_background`；发布 id 后改用任务自有取消信号）。需要部署策略？→ 钩子（`tools/pre-execute` / `ctx.tools.guard()` / `tools/post-execute`），不进工具。会被 PTC mode 程序化调用？→ `output.schema` 按程序化 API 设计（直接返回句柄与字段；人类解释归 `render`）。

## patch 行设计

- 行 id：语义化、全包唯一（用户层按 id 覆盖）。
- insert 还是覆盖前层行：覆盖必须**重述整行每个键**（按行整体替换，非深合并）。
- 默认值策略：给「用户大概率保留」的值，其余交 schema。
- bundle 层 name = 包名；绝对路径只许出现在 `dev/` 覆盖层。

## 脚本化边界（三原则 + 判定问句）

> 本节约束**本工具**，也约束**本工具产出的所有插件与脚本**。

确定性动作交给工程脚本，但**只脚本化「计算 / 变换」，不脚本化「识别 / 匹配」**：

1. **该脚本化（计算 / 变换）**：结构校验、计数、格式化、模板生成、层序比对——已知结构到确定结果，LLM 反而容易算错。
2. **该留 LLM（识别 / 匹配）**：意图识别、语义判断、调用时机评估、相似度——开放输入抽取结构，禁止写进脚本。
3. **发布标准（可移植）**：脚本零第三方依赖；用运行时解析的 base dir；环境值不写死。

**判定问句**（按顺序自问，命中即归属）：

| # | 问句 | 命中 → |
|---|------|--------|
| 1 | 输入是自由文本 / 开放形式，需先理解才能抽取结构吗？ | 留 LLM |
| 2 | 结果依赖语义、常识或上下文吗？ | 留 LLM |
| 3 | 同一输入是否必须得到完全相同的输出（可回归断言）？ | 脚本化 |
| 4 | 计算过程 LLM 会算错吗（版本比较 / 层序 / 计数 / 路径拼接）？ | 脚本化 |
| 5 | 是纯机械变换吗（格式化 / 模板 / 键生成）？ | 脚本化 |

**灰区裁决表**（上表定不了时查这里，禁止临场拍板）：

| 任务 | 归属 | 理由 |
|------|------|------|
| 输出结构校验（schema 校验） | 脚本化 | 已知结构→确定结果；**要不要修**由 LLM 定 |
| 工具 description 质量评估 | 留 LLM | 语义判断（Phase 4 维度 1） |
| 「输出是否符合预期语义」 | 留 LLM | 脚本只比对退出码 / 结构（qa_report 分工） |
| 排序 / 聚合 / 计数 / 版本比较 | 脚本化 | 确定性计算 |
| 启发式静态规则（TS-003 / TOOL-005 等） | 脚本给 [W] 线索 | 语义复核归 Phase 4，不冒充确定性 |

## 文档架构（SSOT 与预算）

> 本节同时约束**本插件（dsh-plugins-builder）**与**它产出的所有插件包**。

三条铁律：
1. **单一事实来源**：任何规范只允许在一个文件里定义一次；其他位置只放指针，禁止复制正文。
2. **入口最小化**：`index.js` 与 README 只放工具注册、安装验证与指针；方法论与流程展开放 `references/`（经 `plugin_guide` 按需读取）。
3. **按触发时机切分**：合并只发生在同一触发时机内。

插件侧同理：契约只写 `cordis.patch.yml` + README Quickstart 一处事实；README 命令必须可逐条复制执行。

预算以 `validate_plugin.js` 的 `DOC_BUDGET` 常量为唯一事实来源，文档中不写具体数字。冗余判定属识别类，不脚本化——归 Phase 4 维度 8。

验收问句：这条规则在几个文件里出现过？> 1 即失败。改一处阈值要改几个文件？> 1 即失败。

## 发布卫生（隐私 / 泄漏）

1. **示例一律占位符**：文档 / 示例 / 脚本 help 文本里的账号、邮箱、真实数据一律占位符。
2. **禁个人绝对路径与账号**：包内文件内容不得出现个人绝对路径（`/Users/<username>`、`C:\Users\<username>`）或账号标识。唯一例外：`dev/` 覆盖层按平台契约必须绝对路径（校验器 SEC-002 对 `dev/` 豁免）。
3. **二进制剥元数据**：图片生成后剥 EXIF / XMP / AIGC 标识，只留图像数据。
4. **凭据铁律**：严禁真实 Token / 密钥；一律配置字段或 `${VAR}` 占位。
